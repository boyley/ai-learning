# 08 · 思维链与推理增强（Chain-of-Thought & Reasoning）

> 让模型"把推理过程一步步写出来"再给答案，能显著提升数学、逻辑、多步推理的准确率；本质是**用更多 Token 换更多"思考步数"**。重要度 ⭐⭐⭐。

## 🎯 一句话核心

思维链（Chain-of-Thought, CoT）不是让模型"更聪明"，而是**逼它把中间推理展开成文字**——每一步推理都成了后续续写的上下文，相当于给了模型一张"草稿纸"和更多计算步骤，从而避免"一步到位"式的瞎猜。

## 📖 核心原理

**为什么"让它一步步想"就能提升准确率？** 要从 [01-llm-overview](01-llm-overview.md) 的本质说起：LLM 是**自回归**的——它一次只预测下一个 Token，且**没有隐藏的内部"思考循环"**，从读到问题到吐出第一个答案 Token，中间只有固定、有限的一遍前向计算。如果强行让它"直接说答案"，复杂问题（如多步算术、逻辑推理）需要的中间计算量就被压进了这一遍前向里，模型只能靠"模式匹配"猜一个最像的答案，很容易错。

**CoT 的魔法在于：把"思考"外化成了 Token。** 当模型先生成"第一步……第二步……"这些推理文字，这些文字会回流进上下文，成为后续每一步续写的依据——**每一步推理都建立在前面已生成的推理之上**（这正是自回归的续写本质）。于是原本要"一口气算完"的难题，被拆成了一连串"看着前面已写好的中间结果、只需再推进一小步"的简单续写。**推理链的长度 ≈ 模型可用的计算步数**——展开得越长，等价于给模型分配了越多的串行计算预算，这也是为什么 CoT 对数学/逻辑这类"深度"任务提升巨大，而对情感分类这类"一步"任务几乎无用。

**一个关键洞察：CoT 是"测试时计算（test-time compute）"的雏形。** 传统上模型能力靠训练时堆参数/数据（scaling law）；CoT 则揭示了另一条轴——**推理时多花算力（多生成推理 Token）也能换准确率**。这条思路后来被推到极致，催生了**推理型模型**（见下文）。同时也点出了 CoT 的代价：换来的准确率是用**更长的输出 = 更多 Token = 更贵更慢**买的。

**Zero-shot vs Few-shot CoT——同一原理的两种触发方式：**
- **Zero-shot CoT**：不给示例，只在问题后加一句"咒语"——最经典的是 **"Let's think step by step"（让我们一步步思考）**。这一句就足以让模型进入"先展开推理再作答"的模式，几乎零成本。
- **Few-shot CoT**：在 Prompt 里给几个**带完整推理过程的示例**（不只是"问题→答案"，而是"问题→推理步骤→答案"），模型会模仿这种"边想边写"的格式。适合特定领域、需要固定推理风格时，效果通常比 Zero-shot 更稳。

## 🔧 关键方法 / 流程 / 架构

**直接回答 vs CoT（同一道题的两种解法）：**

```
问题：小明有 5 个苹果，买了 3 袋、每袋 4 个，吃掉 2 个，还剩几个？

【直接回答 / 一步到位】
   模型：15 个              ← 一遍前向里硬算，易错（这里就错了）

【思维链 CoT / 展开推理】
   模型：先算买的：3 袋 × 4 = 12 个
         加上原有：5 + 12 = 17 个
         减去吃掉：17 − 2 = 15 ... 等一下，17 − 2 = 15 个
         所以还剩 15 个
        （每步基于上一步的中间结果续写，错误更易被"下一步"纠正）
```

> 直觉：直接回答像"心算不打草稿"，CoT 像"列竖式一步步算"——后者慢但对得多。

**进阶方法（在朴素 CoT 之上加"搜索/投票/行动"）：**

| 方法 | 一句话原理 | 适用 | 代价 |
|---|---|---|---|
| **朴素 CoT** | 单条推理链，一路走到底 | 大多数多步推理 | 低 |
| **Self-Consistency** | **采样多条**不同推理路径，对最终答案**投票取多数** | 答案唯一、可比对（数学题） | 中（多次生成） |
| **Tree of Thoughts (ToT)** | 把推理组织成**树**，每个节点是一个"想法分支"，可评估/回溯/剪枝，做**树搜索** | 需要探索多种可能、可回溯的难题（解谜、规划） | 高（多分支+评估） |
| **ReAct** | **推理（Reason）+ 行动（Act）交替**：想一步→调用工具/查资料→看结果→再想 | 需要**外部信息或工具**的任务 | 高（含工具调用） |

```
CoT      ：  想①→想②→想③→答            （一条链）
Self-Cons：  链A→答:15 ┐
            链B→答:15 ├─ 投票 → 15      （多条链取多数）
            链C→答:14 ┘
ToT      ：      ┌想A→…（评估:好，继续）
            想根─┼想B→…（评估:差，剪枝✂）（树搜索+回溯）
                └想C→…
ReAct    ：  想→[查天气工具]→观察结果→想→[查日历]→观察→答（推理+行动交替）
```

> **ReAct 是从"纯推理"通往"Agent"的桥梁**：让模型在推理中穿插工具调用并根据结果继续推理，就是最基础的智能体循环（详见 [22-agent-react](22-agent-react.md)）。

**推理型模型（Reasoning Models，2024–2025 的新范式）：**

o 系列、DeepSeek-R1 等把 CoT 从"用户在 Prompt 里手动触发"变成了**模型内置的能力**。核心区别：
- **训练方式不同**：不再靠人写示例，而是用**强化学习（RL）** 直接奖励"能推出正确答案的长推理链"，让模型自己学会何时该长思考、如何自我检查与回溯。
- **内置长思维链**：调用时无需说"step by step"，模型会**先在内部生成一大段推理**（部分厂商会把这段"思考"折叠或隐藏），再给出精炼答案。
- **能力更强但更贵更慢**：这段隐藏推理会消耗大量 Token（推理时算力），因此**延迟高、成本高**。

| 维度 | 普通对话模型（GPT/Claude 标准版） | 推理型模型（o 系列 / R1 等） |
|---|---|---|
| CoT 从哪来 | 靠 Prompt 手动触发 | 内置、自动长思考 |
| 训练 | SFT + RLHF 对齐 | 额外用 RL 训练推理能力 |
| 强项 | 通用对话、抽取、写作、快响应 | 数学、代码、逻辑、复杂多步推理 |
| 成本/延迟 | 低 | **明显更高**（隐藏推理烧 Token） |
| 何时用 | 简单/常规任务、追求快和省 | 确实需要深度推理时才上 |

## 🔑 要点速记

- CoT = **让模型先写推理过程再给答案**；本质是把"思考"外化成 Token，用**输出长度换计算步数**。
- 为什么有效：LLM 是自回归的、一遍前向算力有限；展开推理让**每步基于前面已生成的中间结果续写**，把难题拆成一串简单续写。
- **Zero-shot CoT**：加一句 **"Let's think step by step"** 即触发；**Few-shot CoT**：示例里带完整推理过程。
- 进阶：**Self-Consistency**（多路径投票）、**Tree of Thoughts**（树搜索+回溯）、**ReAct**（推理+行动交替，通往 Agent）。
- **推理型模型**（o 系列 / DeepSeek-R1）：用 **RL** 训练、**内置长思维链**、无需手动触发；擅长复杂推理但**成本/延迟更高**。
- CoT/推理是**测试时计算**这条能力轴：推理时多花算力也能换准确率，是训练时 scaling 之外的另一条路。
- 铁律：**CoT 让输出更长 = 更贵更慢**；只在多步推理任务上用，简单任务不必强上。

## ❓ 高频面试 / 理解题

**Q：思维链为什么能提升准确率？说到本质。**
A：因为 LLM 是**自回归**模型，从读题到吐第一个答案 Token 只有**一遍固定、有限的前向计算**，没有隐藏的内部思考循环。逼它"直接说答案"，复杂题所需的多步计算被压进这一遍里，只能靠模式匹配硬猜。CoT 把推理**展开成 Token**后，这些推理文字回流进上下文，让**每一步都基于前面已写好的中间结果续写**——等价于把难题拆成一串简单续写，也等价于给模型分配了更多**串行计算步数**。一句话：CoT 是"用输出长度换思考深度"。

**Q：Self-Consistency、Tree of Thoughts、ReAct 分别在朴素 CoT 上加了什么？**
A：朴素 CoT 是**单条链一路走到底**。Self-Consistency 加了"**采样多条链 + 对答案投票取多数**"，用冗余抵消单链的随机错误；ToT 加了"**把推理组织成树、可评估/回溯/剪枝**"，用搜索探索多种可能；ReAct 加了"**推理与工具调用交替**"，让模型能获取外部信息——它也是最基础的 Agent 循环。代价依次升高。

**Q：什么时候该用推理型模型，什么时候别用？**
A：推理型模型（o 系列 / R1）内置长思维链、用 RL 训练，在**数学、代码、复杂逻辑**上明显更强，但每次会生成大量隐藏推理 Token，**延迟和成本都高得多**。判断标准是任务是否"真的需要多步深度推理"：需要就上；而像**信息抽取、分类、简单问答、格式转换**这类"一步"任务，用它纯属浪费——又慢又贵，效果还未必比普通模型好。

## ⚠️ 易错点 / 实践建议

- ⚠️ **CoT 不是免费的**：它让输出显著变长 = **更多 Token = 更贵 + 更慢**。简单任务（分类、抽取、闲聊）强上 CoT，只会白白增加成本和延迟，收益几乎为零。
- ⚠️ **别用推理型模型做简单抽取/分类**：内置长思考会烧掉大量 Token，属于"高射炮打蚊子"——这类任务用普通模型甚至更小的模型即可。
- ✅ **要唯一确定的答案时配 Self-Consistency**：数学、判分等答案可比对的场景，采样多条链投票能明显压低偶发错误率（代价是多次生成）。
- ✅ **推理型模型少手动加"step by step"**：它已内置长思维链，再叠一层 Prompt 咒语可能干扰其原生推理格式，通常直接问、把问题描述清楚即可。
- ✅ **加分认知**：能说清"CoT 的本质是**测试时计算（test-time compute）**——推理时多花算力换准确率，是训练时 scaling law 之外的第二条能力轴"，比只会背"让它一步步想"更显理解深度。
