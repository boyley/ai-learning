# 11 · Embedding 原理（Text Embedding）

> Embedding 把文本（或图片）映射成一个**固定长度的高维向量**，让**语义相近的内容向量距离也近**——它是"语义的数字指纹"，也是语义检索 / RAG 的地基。重要度 ⭐⭐⭐。

## 🎯 一句话核心

Embedding 干的事只有一件：把一段文本压成一个几百到几千维的**定长向量**，且**编码方式保证"意思越像、向量越近"**。有了它，"两句话意思像不像"这个模糊的语义问题，就变成了"两个向量距离多远"这个可以精确计算的数学问题。

## 📖 核心原理

**Embedding 是把离散的文本映射到连续向量空间的函数。** 输入一句话（任意长度），输出一个**固定长度**的向量，例如 768 维、1024 维或 1536 维。关键不在"变成数字"本身——one-hot 编码也是数字——而在于**这个空间是有语义结构的**：`向量("狗")` 和 `向量("小狗")` 距离很近，和 `向量("汽车")` 距离很远。整个高维空间被组织成一张"语义地图"，方向和距离都承载含义。所以人们说 embedding 是文本的"**语义指纹**"：同一个意思无论换什么措辞，指纹都接近；意思变了，指纹就变远。

**为什么模型能学到这种空间？靠对比学习（contrastive learning）等训练目标。** 直觉是：给模型看大量"语义相似的文本对"（如问题-答案、同义句、同一篇文档的相邻段落）和"不相似的文本对"，训练目标就是**把相似对的向量拉近、把不相似对的向量推远**（in-batch negatives、InfoNCE 之类的损失）。反复优化后，模型被迫把"什么和什么意思接近"这一知识编码进向量的几何布局里。这与 LLM"预测下一个 Token"的训练目标不同——embedding 模型的目标直接就是"让语义相似度=向量相似度"，所以它天生适合做检索匹配，而不是生成文本。

**为什么这件事如此有用？因为它把"语义相似度"降维成了"向量距离计算"。** 一旦文本都变成同一空间里的向量，机器就能用余弦相似度 / 内积等廉价运算，在**百万级向量里毫秒级找出"意思最像的"**。这一步是**语义检索、RAG、聚类、推荐、去重、分类**等一切"按意思找/分"的任务的共同底座：RAG 靠它把用户问题和知识库切片在语义上对齐并召回（详见 [14-rag-overview](14-rag-overview.md)）；聚类靠它把相近向量归堆；推荐靠它找"和你喜欢的东西相近"的项。相似度到底怎么算、怎么在海量向量里快速找，见 [12-similarity-ann](12-similarity-ann.md)；向量存哪、怎么建索引，见 [13-vector-database](13-vector-database.md)。

**维度是表达力与成本的权衡。** 维度越高，向量能承载的语义细节越多、表达力越强，但**存储更大、相似度计算更慢、索引更贵**。近年的 **Matryoshka（套娃）表示学习**很巧妙：训练时让向量的**前 k 维就能独立表达大部分语义**，于是同一个 1536 维向量可以**按需截断成 512 / 256 维**来省钱提速，精度只小幅下降——相当于一次编码、多档精度可选。

## 🔧 关键方法 / 流程 / 架构

**文本 → 向量 → 语义空间：**

```
  文本（任意长度）           Embedding 模型             语义向量空间（示意：2D 投影）
 ┌──────────────┐         ┌───────────────┐
 │ "小狗在跑"    │ ──────► │  编码器         │ ──►  [0.02, -0.7, ..., 0.15]   (768/1536 维)
 └──────────────┘         │ (对比学习训练)  │                 │
 ┌──────────────┐         │  输出定长向量   │                 ▼
 │ "幼犬在奔跑"  │ ──────► │                │ ──►  [0.03, -0.68,..., 0.14]
 └──────────────┘         └───────────────┘
                                                语义地图（距离=语义远近）：
                                                   狗族群              交通工具群
                                                 ● 小狗                    ● 汽车
                                                 ● 幼犬  ← 挨得很近         ● 卡车
                                                 ● 狗狗                    ● 火车
                                                          └─ 两个群离得很远 ─┘
        意思越像 → 向量越近；换措辞不改变"指纹"，改变意思才改变"指纹"。
```

**用起来只有两步，但有一条铁律：入库与查询必须同款模型。**

```
① 建库（离线）：文档切片 ──► [Embedding 模型 M] ──► 向量 ──► 存入向量库
② 查询（在线）：用户问题 ──► [必须同一个 M] ──► 查询向量 ──► 算相似度 ──► 召回最近的切片

⚠️ 若①用模型 A、②用模型 B：两组向量根本不在同一个坐标系里，
   算出的"距离"毫无语义意义，检索结果等同随机。换模型必须全库重新编码。
```

**Embedding 模型怎么选（框架无关的评估维度）：**

| 维度 | 说明 |
|---|---|
| 效果 | 看权威榜单（如 MTEB）在**你任务类型 / 你语言**上的检索得分，而非综合分 |
| 维度 | 384/768（轻量快）↔ 1024/1536+（更强更贵）；是否支持 Matryoshka 降维 |
| 语言 | 是否覆盖中文 / 多语；跨语言检索是否需要多语模型 |
| 成本形态 | API 按 Token 计费 vs 开源自托管（数据不出域、可控成本） |
| 最大输入长度 | 单次能编码多长文本，决定切片粒度上限 |

**句向量 vs 词向量：** 早期的 Word2Vec / GloVe 是**词向量**——每个词一个固定向量，无法区分"苹果(水果)"与"苹果(公司)"，也不表达整句意思。现代做的是**句 / 段级 embedding（sentence embedding）**：一次编码整段文本、输出一个能代表整体语义的向量，且**上下文相关**（同一个词在不同句中影响不同）。要点：**Embedding 模型与生成式 LLM 是两类模型**——前者专门产语义向量做匹配，后者产文本做生成；做 RAG 时通常一个 embedding 模型负责"找"、一个 LLM 负责"答"，两者独立选型。

> 一句话补充：**多模态 embedding** 把图片和文字编码进**同一个共享向量空间**（CLIP 的思路），于是"用文字搜图 / 用图搜文"变成同一空间里算距离——跨模态检索由此实现。

## 🔑 要点速记

- Embedding = 把文本映射成**定长高维向量**（如 768/1536 维），**语义近 ⇒ 向量近**，是"语义指纹"。
- 训练直觉：**对比学习**把相似文本拉近、不相似推远，把"什么和什么像"编码进向量几何。
- 核心价值：把**语义相似度**变成**向量距离计算**——语义检索 / RAG / 聚类 / 推荐 / 分类的共同地基。
- 维度是**表达力 vs 成本**权衡；**Matryoshka** 支持一次编码、按需截断降维省钱。
- 🔒 铁律：**入库与查询必须用同一个 embedding 模型**，否则向量不在同一坐标系，相似度无意义；换模型要全库重编码。
- 选型看**你任务 / 你语言**上的检索效果（如 MTEB），而非综合分；再权衡维度、成本、输入长度。
- 现代用**句 / 段级 embedding**（上下文相关），非早期固定词向量；**embedding 模型 ≠ 生成 LLM**，是两类模型。
- **多模态 embedding**（CLIP 思路）把图文放进共享空间，实现跨模态检索。

## ❓ 高频面试 / 理解题

**Q：Embedding 到底是什么？为什么"语义相似"能变成"距离计算"？**
A：Embedding 是把任意文本映射成一个定长高维向量的函数，关键是这个向量空间**有语义结构**——意思越接近的文本，向量距离越近。它靠对比学习训练：让相似文本对的向量互相靠拢、不相似的推远，从而把"什么和什么意思像"这一知识编码进向量的几何布局。一旦文本都成了同一空间里的向量，"两段话意思像不像"就等价于"两个向量距离多远"，机器可以用余弦相似度在百万向量里毫秒级找出最像的——模糊的语义问题被降维成了廉价的数学运算。

**Q：为什么入库和查询必须用同一个 embedding 模型？**
A：不同模型学出的是**不同的向量空间**——同一句话被模型 A 和模型 B 编码出的向量，维度、坐标含义、几何布局都不一样。如果建库用 A、查询用 B，两组向量根本不在同一个坐标系里，算出的"距离"不反映任何语义关系，检索结果等同随机。所以入库与查询必须同款模型；一旦要换模型，整个向量库都得用新模型重新编码。

**Q：Embedding 模型和 LLM（如 GPT/Claude）是一回事吗？**
A：不是，是两类模型。LLM 的训练目标是"预测下一个 Token"、产出文本，擅长生成；Embedding 模型的训练目标直接是"让语义相似度=向量相似度"、产出定长语义向量，擅长匹配检索。做 RAG 时通常分工：embedding 模型负责把问题和知识切片对齐、召回相关内容（"找"），LLM 负责基于召回的材料生成回答（"答"），两者独立选型、独立计费。

**Q：向量维度是不是越高越好？**
A：不是,是表达力与成本的权衡。维度越高能承载的语义细节越多、召回可能更准，但存储、相似度计算、索引都更贵更慢。实践中要按任务在效果和成本间取舍；Matryoshka 表示学习让向量的前若干维就能独立表达主要语义，于是可以对同一向量**按需截断降维**（如 1536→512），大幅省钱提速而精度只小降。

## ⚠️ 易错点 / 实践建议

- ⚠️ **最常见的坑：建库和查询用了不同 embedding 模型（或同模型不同版本）**——向量空间不一致，检索直接失效且不易察觉；换模型必须全量重建索引。
- ⚠️ **别只看榜单综合分选模型**——要看它在**你的任务类型（检索/分类）和你的语言（中文/多语）**上的得分；通用第一名未必最适合你的场景。
- ⚠️ **归一化要一致**：用余弦相似度前通常需对向量归一化（L2 normalize），入库和查询的处理方式必须相同，细节见 [12-similarity-ann](12-similarity-ann.md)。
- ✅ **注意最大输入长度**：超长文本会被截断而丢语义，应先按 embedding 模型的窗口做合理切片（分块策略是 RAG 的关键一环，见 [14-rag-overview](14-rag-overview.md)）。
- ✅ **加分认知**：能说清"embedding 把语义相似度降维成向量距离，是 RAG/检索的地基，且它与生成 LLM 是两类模型"，比只会背"文本转向量"更显对原理的理解。
