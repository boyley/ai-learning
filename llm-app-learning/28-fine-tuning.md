# 28 · 微调与模型定制（Fine-Tuning）

> 微调是在已训练好的模型上，用特定领域/任务数据**继续训练**，改变它的**能力、风格、输出格式、垂直语感**——它改的是"模型本身"，不是"调用法（Prompt）"，也不是"喂知识（RAG）"。重要度 ⭐⭐⭐。

## 🎯 一句话核心

微调 = **用你的数据接着练模型，把某种"行为/风格/格式"固化进参数里**。它擅长改**怎么说话（风格/格式/垂直语感）**，不擅长补**说什么事实（知识）**——补知识是 RAG 的活。选型铁律：**能 Prompt 解决就别 RAG，能 RAG 解决就别微调**（成本从低到高）。

## 📖 核心原理

**微调是三段式训练范式的"再来一次"。** 回顾 [01-llm-overview](01-llm-overview.md)：一个对话模型是走完"预训练（学知识）→ SFT（学听话）→ 对齐 RLHF/DPO（学分寸）"三步的产物。微调本质就是**在这条流水线的下游，用你自己的小规模高质量数据再跑一轮训练**，把模型的参数往你想要的方向轻推——让它形成固定的回答风格、稳定的输出格式、或某个垂直领域的"语感"。它**不是"记住新事实"**，而是**调整模型生成文本的分布倾向**。

**为什么微调改的是"能力/风格"而不是"知识"？** 因为微调数据量通常只有几百到几万条，相对预训练的万亿 Token 是沧海一粟——用这点数据想"塞进"大量新事实，既学不牢（模型不会因为看几遍就可靠记住），又容易**过拟合成幻觉**（学会了"这类问题要自信地编一个答案"的模式）。但用它来**校准行为模式**却非常有效：几百条"这样格式回答"的样例，就足以让模型稳定地按你要的腔调、结构、术语说话。**知识是"内容"，风格/格式是"模式"——微调擅长教模式，不擅长灌内容。**

**微调改变的四类东西（记住这四个词就懂何时该微调）：**
- **能力**：把通用模型对齐到某个特定任务（如专门做医疗分诊、法律条款抽取），小模型微调后单任务可逼近大模型。
- **风格**：固定语气/人设/品牌口吻（客服话术、角色扮演一致性）。
- **输出格式**：稳定产出特定结构（固定 JSON schema、特定报告模板），减少格式跑偏。
- **垂直语感**：领域黑话、专业术语、行业表达习惯（金融、法律、医学的"说话方式"）。

**一个关键的成本视角——微调能"压缩 Prompt"。** 如果你现在靠一段很长的 System Prompt（几百上千 Token 的格式说明+few-shot 示例）来约束模型，每次调用都要重复付这段 Token 的钱。把这些示例"训"进模型后，就能用很短的 Prompt 达到同样效果——**高频调用场景下，微调是一次性投入换长期单价下降**。

## 🔧 关键方法 / 流程 / 架构

### 微调类型全景

| 类型 | 改什么 | 成本 | 何时用 |
|---|---|---|---|
| **全参微调 Full Fine-Tuning** | 更新**全部**参数 | 极高（算力/显存/易灾难性遗忘） | 有大量数据+算力、要深度改造能力 |
| **PEFT / LoRA**（主流） | 冻结原模型，只训**少量低秩适配器** | 低（省显存/可插拔） | 绝大多数场景的默认选择 |
| **QLoRA** | 4-bit 量化基座 + LoRA | 极低（单卡可跑） | 显存紧张、消费级 GPU 也能微调 |
| **指令微调 SFT** | 教模型听指令/对话格式 | 中 | 把 base 模型变成能对话的 instruct 模型 |
| **偏好对齐 DPO/RLHF** | 用"好/坏"偏好对校准 | 高 | 让输出更符合人类偏好（有用/无害） |

**LoRA（Low-Rank Adaptation）为什么是主流——重点理解。** 直接改整个大模型（数十亿参数）又贵又危险。LoRA 的洞见是：**微调时参数的"改变量"其实是低秩的**，可以用两个小矩阵 `A×B` 来近似表示这个改变量。于是**冻结原模型的全部权重不动，只在旁边挂上一小撮可训练的低秩矩阵**（往往只占原参数的 0.1%~1%）。

```
        原始权重 W（冻结，不训练）
输入 x ─────────────┬──────────────▶ 原始输出
                    │
                    └──▶ [A]·[B] ──▶ 加到输出上（只训练这一小撮）
                         低秩适配器（LoRA）
```

这带来三个杀手级好处：
- **省**：显存/算力/存储都大降，一张卡就能微调大模型；QLoRA 再把基座量化到 4-bit，成本进一步压到消费级。
- **稳**：原模型权重没动，**灾难性遗忘风险小**（相比全参微调）。
- **可插拔**：一个基座 + 多个 LoRA 适配器（每个几十 MB），按任务动态切换/组合，一份基座服务多个业务。

### 决策核心：Prompt vs RAG vs 微调 怎么选

三者解决的是**完全不同的问题**，不是互相替代，而是"先便宜的、不够再上贵的"，且**可叠加**。

| 维度 | Prompt 工程 | RAG（检索增强） | 微调 Fine-Tuning |
|---|---|---|---|
| **改的是** | 调用法（怎么问） | 喂给它的**知识** | 模型本身（能力/风格/格式） |
| **最适合** | 快速试、调行为 | 补**动态/私域/最新知识** | 固定风格/格式、垂直语感、压 Prompt |
| **知识更新** | 改提示词即可 | **改数据库即时生效** | 要**重新训练**（慢/贵） |
| **可溯源** | — | ✅ 能给出处 | ❌ 混进参数，不可溯源 |
| **成本** | 最低 | 中（要检索管线） | 高（要数据+算力+持续维护） |
| **数据要求** | 无 | 文档语料 | **高质量标注样本** |
| **典型场景** | 通用任务、原型 | 企业知识库问答、客服 | 固定 JSON 输出、品牌口吻、领域小模型 |

**决策树（务必按这个顺序走）：**

```
需求来了
  │
  ├─ 改 Prompt 能解决吗？（换问法/加示例/加约束）
  │     └─ 能 → 用 Prompt 工程，收工（最轻、最便宜）
  │
  ├─ 缺的是"知识/事实"吗？（最新、私域、需溯源）
  │     └─ 是 → 上 RAG（补知识、动态、可溯源，详见 14-rag-overview）
  │
  └─ 缺的是"风格/格式/垂直语感/单价"吗？
        └─ 是，且有高质量数据 → 才考虑微调
              │
              └─ 首选 PEFT/LoRA（省），显存紧再上 QLoRA

⚡ 三者可叠加：微调管"怎么说"（风格/格式）+ RAG 管"说什么"（知识）
   典型组合 = 用 LoRA 固定客服话术和输出结构，用 RAG 注入实时产品文档
```

### 数据与流程

微调的成败**七分在数据**：
1. **数据质量 > 数量**：几百条精挑细选的高质量样本，胜过几万条噪声数据。脏数据会被模型忠实学进去。
2. **格式对齐**：训练样本要和推理时的调用格式一致（同样的 system/user/assistant 结构、同样的 schema）。
3. **多样性与代表性**：覆盖真实分布的各种情况，避免只教一种模式导致过拟合。
4. **划分评估集**：留出验证/测试集，用可量化指标评估微调前后的效果（任务准确率、格式合规率、风格一致性），**别凭感觉说"变好了"**。
5. **小步快跑**：先小数据+小 epoch 验证方向，再逐步加量；盯住验证集 loss，防过拟合。

## 🔑 要点速记

- 微调 = **用你的数据继续训模型**，改的是**能力/风格/输出格式/垂直语感**，不是知识。
- **全参微调**贵且易灾难性遗忘；**PEFT/LoRA** 冻结原模型只训低秩适配器，省/稳/可插拔，是**主流默认**；**QLoRA** = 量化 + LoRA，最省。
- **SFT** 教听指令/对话，**DPO/RLHF** 用偏好对齐——都是微调家族。
- 选型铁律：**Prompt → RAG → 微调**，成本从低到高，先试轻的。
- **RAG 补知识**（动态/可溯源/便宜）；**微调改风格/格式/垂直语感**（固定/贵/要数据）。二者**可叠加**：微调管"怎么说"+ RAG 管"说什么"。
- 何时该微调：固定风格/输出格式、垂直领域语感、**压缩长 Prompt 降单价**、私有小模型对齐特定任务。
- **微调不补知识**：别用它塞事实，学不牢还诱发幻觉，更新还得重训。
- 数据**质量 > 数量**，格式要和推理一致，务必留评估集量化前后效果。

## ❓ 高频面试 / 理解题

**Q：RAG 和微调到底怎么选？能不能只用微调把知识"训进去"？**
A：先分清二者管的事：**RAG 补知识、微调改行为**。需要最新/私域/可溯源的**事实**，用 RAG——改数据库就即时生效，还能给出处；需要固定**风格/输出格式/垂直语感**或压缩长 Prompt，才用微调。**不能靠微调塞知识**：微调数据量太小，事实学不牢，而且会把模型训成"遇到这类问题就自信地编"，反而加重幻觉（详见 [05-hallucination](05-hallucination.md)）；知识一变还得重新训。实践顺序永远是 **Prompt → RAG → 微调**，且二者常叠加：LoRA 管话术和格式，RAG 注入实时知识。

**Q：为什么 LoRA 成了微调的主流，它凭什么省？**
A：全参微调要更新数十亿参数，显存/算力/存储都极高，还容易灾难性遗忘。LoRA 基于一个观察——微调带来的**权重改变量是低秩的**，可以用两个小矩阵相乘来近似。于是它**冻结原模型全部权重，只训练旁挂的低秩适配器**（往往仅占原参数 0.1%~1%）。好处三连：省（单卡可训，QLoRA 量化后更省）、稳（原权重没动，遗忘风险小）、可插拔（一个基座挂多个几十 MB 的适配器，按任务切换）。

**Q：什么情况下 Prompt 和 RAG 都不够、必须微调？**
A：四种典型信号：①需要**稳定固定的输出格式**（如严格 JSON schema），Prompt 约束总跑偏；②需要固定的**品牌口吻/人设一致性**；③需要**垂直领域语感/黑话**，通用模型说话"不像内行"；④**高频调用**下想把一大段 few-shot Prompt "训"进模型来**降低单次 Token 成本**。此外还有私有小模型想在特定任务上逼近大模型能力。注意前提是**有高质量标注数据**，否则免谈。

## ⚠️ 易错点 / 实践建议

- ⚠️ **别用微调补知识**：这是最常见误区。塞事实进参数学不牢、诱发幻觉、更新要重训——要事实就上 RAG。微调只教"模式/风格/格式"。
- ⚠️ **灾难性遗忘（catastrophic forgetting）**：全参微调用窄数据猛训，模型会"学了新的忘了旧的"，通用能力退化。优先用 LoRA（冻结原权重风险小）、控制学习率和 epoch、必要时混入通用数据。
- ⚠️ **微调是持续维护成本，不是一锤子买卖**：基座升级、业务变化、数据漂移都可能要求重训和重新评估，别低估长期投入。
- ✅ **数据质量决定一切**：脏数据会被忠实学进去。宁可几百条精标，不要几万条噪声；训练格式必须和推理格式一致。
- ✅ **一定要量化评估**：留出测试集，用任务准确率/格式合规率/风格一致性等指标对比微调前后，别凭感觉。评估方法是微调闭环的必备一环。
- ✅ **加分认知**：能说清"RAG 补知识、微调改行为，二者叠加（微调管怎么说 + RAG 管说什么）"，比只会背"微调更强"更显理解本质——这正是 [01-llm-overview](01-llm-overview.md) 里 Prompt/RAG/微调三手段分工的落地。
