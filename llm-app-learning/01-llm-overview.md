# 01 · 大模型概览与范式（LLM Overview & Paradigm）

> 大语言模型（LLM）是在海量文本上预训练的**生成式概率模型**，本质是"给定上文预测下一个 Token"；理解它的**训练范式（预训练→微调→对齐）** 和**能力边界**，是做好一切 LLM 应用的地基。重要度 ⭐⭐⭐。

## 🎯 一句话核心

大模型不是"知识库"也不是"推理引擎"，而是一个**超大规模的"下一个 Token 概率预测器"**——它的所有惊艳能力（对话、写代码、推理）和所有毛病（幻觉、不稳定）都源于这一个本质：**按概率续写最像样的文本**。

## 📖 核心原理

**LLM 的本质是自回归语言建模（autoregressive language modeling）。** 训练目标极其简单：给定前面的文本，预测下一个 Token 的概率分布。把这个"文字接龙"在**万亿级 Token 语料 + 千亿级参数**上做到极致，就"涌现"出了理解、翻译、推理、写代码等能力——这就是**规模效应（scaling law）**：能力随参数量、数据量、算力增长而提升。

**为什么"预测下一个词"能产生智能？** 因为要准确预测下文，模型被迫在参数里**压缩了世界知识、语法、逻辑、常识**。要续写"法国的首都是___"，它得"知道"巴黎；要续写一段代码，它得"理解"语法和意图。**智能是压缩的副产品**——但也正因为它本质是概率续写，所以会**一本正经地编造**看似合理实则错误的内容（幻觉，详见 [05-hallucination](05-hallucination.md)）。

**现代 LLM 的三段式训练范式（这是应用者必须理解的）：**

1. **预训练（Pre-training）**：在海量无标注文本上做自回归预测，学到通用语言能力和知识。产出"基座模型 base model"——博学但不听话、不会对话。**成本极高（这步只有大厂做）**。
2. **监督微调（SFT, Supervised Fine-Tuning）**：用高质量"指令-回答"对训练，让模型学会**听从指令、按对话格式回答**（instruction following）。产出"指令模型"。
3. **对齐（Alignment，如 RLHF/DPO）**：用人类偏好数据进一步调，让回答更**有用、无害、诚实（helpful/harmless/honest）**。这步让模型"懂分寸"。

> 应用开发者几乎只接触第 2、3 步之后的"对话模型"，通过 **Prompt（调用法）、RAG（补知识）、微调（改能力）** 三种手段驾驭它（三者怎么选见 [28-fine-tuning](28-fine-tuning.md)）。

**LLM 的能力边界（做应用必须心里有数）：**
- ❌ **不知道训练截止后的事**（知识有时效）→ 靠 RAG/工具补。
- ❌ **不擅长精确计算、实时信息**→ 靠工具调用补（[20-function-calling](20-function-calling.md)）。
- ❌ **会幻觉、不稳定、不可完全复现**→ 靠 RAG + 结构化约束 + 评估兜底。
- ❌ **无状态、无记忆**→ 记忆靠应用层维护（每次重传历史）。
- ✅ 擅长：语言理解/生成、总结、抽取、分类、翻译、代码、基于给定材料作答。

## 🔧 关键方法 / 流程 / 架构

**从"基座模型"到"你用的对话 API"：**

```
海量文本语料
   │  ① 预训练（自监督，预测下一个Token）      ← 只有大厂做，成本千万美元级
   ▼
[基座模型 Base]  博学但不听话、只会续写
   │  ② SFT 监督微调（指令-回答对）
   ▼
[指令模型 Instruct]  会听指令、会对话
   │  ③ 对齐 RLHF/DPO（人类偏好）
   ▼
[对话模型 Chat]  有用/无害/诚实  ←── 你调用的 GPT/Claude/通义 就是这个
   │
   ▼  应用层用三种手段驾驭：
   ├─ Prompt 工程（改调用法，最轻）
   ├─ RAG（补外部知识，主流）
   └─ 微调（改模型能力/风格，最重）
```

**主流模型格局（2024–2026，概念级了解即可）：**

| 类别 | 代表 | 特点 |
|---|---|---|
| 闭源顶级 | GPT 系列、Claude 系列、Gemini | 能力最强、API 调用、按 Token 计费 |
| 开源可自托管 | Llama、Qwen(通义)、DeepSeek、Mistral | 可私有化部署、可微调、数据不出域 |
| 推理型模型 | o 系列、DeepSeek-R1 等 | 内置长思维链，擅长复杂推理（详见 [08-cot-reasoning](08-cot-reasoning.md)） |

## 🔑 要点速记

- LLM 本质 = **自回归"预测下一个 Token"的概率模型**；能力和幻觉同源于此。
- **规模效应（scaling law）**：能力随参数/数据/算力增长而涌现。
- 三段式范式：**预训练（学知识）→ SFT（学听话）→ 对齐 RLHF/DPO（学分寸）**。
- 基座模型 base（博学不听话）vs 指令/对话模型（会对话）——你用的是后者。
- 应用层三手段：**Prompt（调用法）/ RAG（补知识）/ 微调（改能力）**。
- 能力边界：不知新事、不会精算、会幻觉、无记忆 → 分别用 RAG/工具/评估/对话历史补。
- **生成式**（generative）而非判别式；**通用**（一个模型多任务，零样本即用）。

## ❓ 高频面试 / 理解题

**Q：大模型为什么会"涌现"出智能？它到底在做什么？**
A：它做的唯一一件事是**预测下一个 Token 的概率分布**（自回归语言建模）。之所以能涌现出理解、推理、写代码等能力，是因为要在万亿级语料上准确预测下文，模型被迫把世界知识、语法、逻辑、常识都**压缩进了参数**——智能是"极致压缩 + 规模效应"的副产品。也正因本质是概率续写，它才会幻觉。

**Q：预训练、SFT、RLHF 三步各解决什么？**
A：预训练在海量无标注文本上自监督学习，让模型**博学**（有知识和语言能力），但只会续写、不听指令；SFT 用指令-回答对训练，让它**学会听从指令、按对话格式回答**；RLHF/DPO 用人类偏好数据对齐，让回答更**有用、无害、诚实**。一句话：预训练学知识、SFT 学听话、对齐学分寸。

**Q：既然大模型这么强，为什么还需要 RAG 和工具调用？**
A：因为 LLM 有硬边界：①知识停在训练截止日，不知最新/私域信息；②不擅长精确计算和实时数据；③会幻觉。RAG 把外部/最新/私域知识检索出来喂给它（补知识、可溯源），工具调用让它能查数据库/调 API/精确计算（补能力）。这些恰好补上模型本身做不到的部分。

## ⚠️ 易错点 / 实践建议

- ⚠️ **别把 LLM 当"数据库"或"搜索引擎"**——它是概率生成器，不保证事实正确；需要准确事实就上 RAG + 溯源，不要直接信它的"记忆"。
- ⚠️ **别把 LLM 当"确定性函数"**——同样输入可能不同输出（采样随机性，详见 [04-sampling-decoding](04-sampling-decoding.md)）；需要稳定就降温度 + 结构化输出 + 校验。
- ✅ **先想清楚用哪种手段**：能改 Prompt 解决就别上 RAG，能 RAG 解决就别微调——成本从低到高（[28-fine-tuning](28-fine-tuning.md)）。
- ✅ **区分 base 与 chat 模型**：base 模型不会对话（只续写），做应用要用 instruct/chat 版本；微调时选对基座。
- ✅ **加分认知**：能说清"能力和幻觉同源于'预测下一个 Token'"，比只会背概念更显理解本质——这也是所有 AI 应用工程手段（RAG/评估/护栏）的存在理由。
