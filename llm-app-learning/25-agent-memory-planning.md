# 25 · Agent 记忆与规划（Memory & Planning）

> LLM 本身**无状态、无记忆、不会自动分解目标**；要让 Agent 能跑长任务、跨会话记事、把大目标拆成可执行步骤，就必须在**应用层**搭出「记忆系统 + 规划系统 + 反思闭环」。重要度 ⭐⭐。

## 🎯 一句话核心

Agent = **LLM（大脑）+ 工具（手脚）+ 记忆（笔记本）+ 规划（做事的章法）**。记忆解决「模型天生记不住」，规划解决「模型不会自己拆解长任务」，反思解决「模型一次做不对」——三者都是**外挂在无状态模型之外的工程结构**，模型只负责每一步的推理。

## 📖 核心原理

**为什么 Agent 必须有记忆？** 因为 LLM 是无状态的（呼应 [01-llm-overview](01-llm-overview.md)）：每次调用都是独立的一次「续写」，模型参数里不会新增你刚说过的话。它唯一「记得」的东西，就是**这一次请求里被塞进上下文窗口的 Token**。可一旦任务变长（多轮对话、多步工具调用、跨天跨会话），历史会迅速超出窗口，模型就会「失忆」。所以**记忆不是模型的能力，而是应用替它维护的外部状态**——把该记的历史、事实、经验存起来，在需要时再喂回上下文。这就是 Agent 记忆系统存在的根本理由。

**为什么要分层记忆？** 因为不同信息的**时效、容量、检索方式**完全不同。当前任务正在用的上下文（短期）必须**完整、即时、放进窗口**；而跨会话的海量历史（长期）不可能全塞进窗口，只能**存到外部、按需检索召回**。这天然映射出「短期工作记忆 / 长期持久记忆」两层，长期记忆内部又按内容性质细分为**情景记忆（episodic，发生过的事）、语义记忆（semantic，事实与知识）、程序记忆（procedural，技能与操作套路）**——这套划分借鉴了认知科学，本质是为「什么该记、怎么存、怎么取」提供结构。长期记忆的实现思路几乎就是把 RAG 用在「记忆」上：**写入时向量化存库，读取时按相似度检索召回**（详见 [14-rag-overview](14-rag-overview.md)）。

**为什么要规划（Planning）？** 因为复杂任务不是一步能完成的，而 LLM 一次前向推理只能产出一段文本，天然不擅长「长程、多步、带依赖」的目标。规划的本质是**任务分解（task decomposition）**：把一个大目标拆成有序（或有依赖关系）的子任务，让每个子任务小到模型一步能可靠完成，再把它们串起来。规划还决定 Agent 的**行动节奏**：是「先想好整张蓝图再执行」，还是「走一步看一步、根据反馈动态调整」——这直接影响 Agent 在开放、不确定环境里的鲁棒性。

**为什么要反思（Reflection）？** 因为 LLM 会犯错、会幻觉、一次未必做对；如果没有自检，错误会沿着规划链**逐步累积放大**。反思就是让 Agent **评估自己的中间结果并据此改进**——这是把「生成」和「评判」拆成两个角色的思想（呼应 evaluator-optimizer 模式，见 [23-agent-patterns](23-agent-patterns.md)），用额外的推理换取更高的正确率。

> 一句话串起来：**记忆让 Agent「记得住」，规划让它「拆得开」，反思让它「纠得正」**——三者共同把「一次性的概率续写」升级成「能持续推进的自主行为」。

## 🔧 关键方法 / 流程 / 架构

**Agent 记忆分层 + 规划循环总览：**

```
                       ┌───────────────── Agent 大脑 (LLM) ─────────────────┐
   用户目标 ──▶ 规划 Planning ─▶ 子任务队列 ─▶ 执行(调工具) ─▶ 观察结果 ─┐  │
                    ▲                                                     │  │
                    │            反思 Reflection：结果达标? ◀────────────┘  │
                    └──────────── 不达标→改计划/重做  达标→下一子任务 ──────┘
                       │(读)                                    │(写)
        ┌──────────────┴───────────── 记忆系统 ────────────────┴──────────────┐
        │  短期记忆（工作记忆）：当前对话/任务上下文 —— 就在窗口内，受长度限制  │
        │        └ 满了怎么办：截断 / 摘要压缩 / 移入长期（见 06 上下文工程）   │
        │                                                                     │
        │  长期记忆（持久化，外部存储 + 向量检索召回，RAG-for-memory）：        │
        │        ├ 情景 episodic ：发生过的对话/事件（“上次用户说过…”）        │
        │        ├ 语义 semantic ：抽出的事实/偏好（“用户是 Java 后端”）       │
        │        └ 程序 procedural：可复用技能/操作套路（“部署流程按这几步”）  │
        └─────────────────────────────────────────────────────────────────────┘
```

**一、记忆的四个动作（写入 / 检索 / 遗忘 / 压缩）**

| 动作 | 做什么 | 关键设计 |
|---|---|---|
| **写入 write** | 把值得记的信息存进长期记忆 | 存原文还是存抽取后的事实？何时触发写入（每轮 / 任务结束 / 显式命令）？去重 |
| **检索 retrieve** | 需要时召回相关记忆塞回上下文 | 向量相似度 + 时间新近度 + 重要度的**混合打分**；控制召回条数 |
| **遗忘 forget** | 淘汰过期/无用记忆 | 按时间衰减、访问频率、显式失效；避免记忆无限膨胀 |
| **压缩 summarize** | 把长历史摘要成短表示 | 滚动摘要（rolling summary）替代逐字历史，省窗口又保信息 |

> 短期记忆的窗口管理（截断、滚动摘要、要点提炼）本质是上下文工程问题，详见 [06-context-engineering](06-context-engineering.md)；长期记忆的向量存取则是把 [14-rag-overview](14-rag-overview.md) 的检索思路搬到「记忆」上。

**二、规划策略谱系（从静态到动态）**

| 策略 | 思路 | 适用 / 权衡 |
|---|---|---|
| **先规划后执行（Plan-and-Execute）** | 先由 LLM 产出完整计划（子任务列表），再逐条执行 | 步骤清晰、可并行、可审计；缺点：环境一变计划就失效 |
| **边做边调（ReAct）** | 思考→行动→观察循环，每步根据反馈决定下一步 | 对不确定环境鲁棒、能纠偏；缺点：步数多、易兜圈、成本高（见 [22-agent-react](22-agent-react.md)） |
| **树/图搜索（如 ToT / LATS）** | 展开多条候选路径、打分回溯，选最优分支 | 解题质量高；缺点：调用量爆炸、贵、慢，仅用于高价值难题 |

实践里常**混合**：先 Plan 出大框架，执行中用 ReAct 循环处理每个子任务的不确定性，遇阻则**重规划（replan）**。

**三、反思 / 自我批判（Reflection / Self-Critique）**

```
执行结果 ──▶ [Critic 角色] 用评判标准打分/找问题 ──▶ 有问题?
                                                    ├ 是 → 生成改进意见 → 重做该步
                                                    └ 否 → 采纳，进入下一步
```
把「做」和「评」分成两个 Prompt/角色（甚至两次调用），用一轮额外推理显著降低错误——这正是 evaluator-optimizer 的落地（[23-agent-patterns](23-agent-patterns.md)）。

**四、工具选择（工具一多，模型选不对）**

工具少时，把所有工具描述都放进上下文即可（Function Calling 机制见 [20-function-calling](20-function-calling.md)）。工具一多（几十上百个），全塞进窗口既**费 Token 又干扰判断**，模型容易选错工具。解法是 **RAG-over-tools（工具检索）**：把每个工具的名称/描述向量化建索引，先根据当前子任务**检索出 Top-K 个候选工具**，只把这几个的定义喂给模型再让它选。此外，**清晰、无歧义、带用途和参数说明的工具描述**本身就是选对工具最有效的杠杆——工具描述写得好，比任何检索技巧都管用。

## 🔑 要点速记

- Agent = **LLM + 工具 + 记忆 + 规划**；记忆和规划都是**外挂在无状态模型外的工程结构**。
- 记忆分层：**短期（工作记忆，窗口内、要管理）/ 长期（持久化，向量库存取召回）**；长期内部分**情景 / 语义 / 程序**三类。
- 长期记忆 = **把 RAG 用在「记忆」上**：写入时向量化，检索时按相似度+新近度+重要度混合召回。
- 记忆四动作：**写入 / 检索 / 遗忘 / 压缩摘要**——遗忘和压缩是防「记忆膨胀」的关键。
- 规划核心是**任务分解**；策略谱系：**Plan-and-Execute（静态）↔ ReAct（动态）↔ 树/图搜索（高成本高质量）**，常混合并支持 **replan**。
- **反思 / self-critique** = 把「做」与「评」拆开（evaluator-optimizer），用额外推理换正确率、防错误累积。
- 工具多时用 **RAG-over-tools 先检索候选工具**；写好**工具描述**是选对工具的第一杠杆。

## ❓ 高频面试 / 理解题

**Q：LLM 明明有上下文窗口，为什么还需要单独的「记忆系统」？**
A：因为窗口只是**短期工作记忆**——它容量有限、且每次调用独立（模型无状态，见 [01-llm-overview](01-llm-overview.md)），长任务的历史很快超窗、跨会话更是一清空就没了。真正的「记忆」必须由**应用层在外部持久化**：该记的事实/经验存进（向量）库，用时再检索召回塞回窗口。所以窗口是「桌面上摊开的纸」，记忆系统才是「归档的档案柜」，两者分工不同、缺一不可。

**Q：短期记忆和长期记忆怎么分工？长期记忆为什么常用向量库？**
A：短期记忆是**当前任务的上下文**，直接放窗口内，特点是完整、即时但受长度限制，满了要靠截断/摘要压缩管理；长期记忆是**跨会话的海量历史**，塞不进窗口，只能存外部、**按需检索**。用向量库是因为记忆检索的诉求是「按语义相关性找回该用的那几条」，正是 RAG 的能力（[14-rag-overview](14-rag-overview.md)）——所以长期记忆本质是 RAG-for-memory：写入即向量化，读取按相似度（叠加时间新近度、重要度）召回。

**Q：Plan-and-Execute 和 ReAct 的规划有什么区别？怎么选？**
A：Plan-and-Execute 是**先想好整张计划再逐步执行**，适合步骤清晰、可预测的任务，透明可审计、还能并行，但环境一变计划就僵；ReAct 是**思考-行动-观察的动态循环**，每步看反馈再决定下一步，对不确定/开放环境鲁棒、能纠偏，代价是步数多、易兜圈、更贵（[22-agent-react](22-agent-react.md)）。实践常**混合**：Plan 出大框架，子任务内用 ReAct 处理不确定性，卡住就重规划（replan）。

**Q：反思（Reflection）为什么能提升 Agent 的可靠性？**
A：因为 LLM 一次未必做对，且错误会沿规划链累积放大。反思把「生成」和「评判」拆成两个角色：先做、再由一个 Critic 用标准去挑毛病，有问题就带着改进意见重做——用一轮额外推理换取更高正确率（即 evaluator-optimizer 模式，[23-agent-patterns](23-agent-patterns.md)）。本质是让 Agent「自己检查作业」，在错误传播前拦下它。

## ⚠️ 易错点 / 实践建议

- ⚠️ **记忆膨胀**：只写不删会让长期记忆无限增长，既贵又拖慢检索、还稀释相关性。必须配**遗忘（时间衰减/低频淘汰/显式失效）+ 压缩摘要**，把「记住一切」改成「记住有用的」。
- ⚠️ **检索噪音**：召回的记忆若不相关，等于往上下文里注入干扰，反而误导模型（记忆版的「检索噪音」，同 RAG）。要控制召回条数、用**相似度+新近度+重要度混合打分**，宁缺毋滥。
- ⚠️ **规划错误累积**：Plan-and-Execute 若前面某步错了却不检查，后续全建在错误之上。要么用 ReAct 边做边校，要么每步加**反思/校验**，并允许 **replan**，别让错误一路滚下去。
- ⚠️ **工具选择干扰**：工具几十上百个还全塞进上下文，模型会选错、也费 Token。上 **RAG-over-tools** 先筛候选，并把**工具描述写清楚（用途、参数、边界）**——描述质量比检索技巧更决定成败。
- ✅ **别过度设计**：不是所有 Agent 都需要三层记忆和树搜索。简单任务一个上下文窗口就够；先用最轻的结构，任务复杂到「记不住/拆不开/做不对」时再逐层加记忆、规划、反思。
